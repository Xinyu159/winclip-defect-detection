# 级联档位对比 —— 多尺度窗口塔值多少算力

> **本报告经历三次自我证伪。修订历史见 §0,请先读它 —— 前两版的结论都是错的。**

生成:2026-09-10 | 本机 CPU (13th Gen Intel, OpenVINO 2026.3.1, INT8 CPU 推理)
数据:MVTec 5 类,**每个类均为该类的全量测试集**(缺陷 84/89/63/93/119 张),
4-shot gallery,seed42 采样

---

## 0. 修订历史(三次被推翻的结论)

### v1:"L1 与 L1+3×3 逐位完全相同 → 窗口塔贡献为零"

**错。** 根因是档位定义 bug:

```python
scales = [('w3', idx3, 'large')]        # ← 无条件带 3×3
if level == 'full':
    scales.append(('w5', idx2, 'mid'))
```

`L1` 与 `L1+3×3` 拿到同一个 scales 列表,算的是同一件事。
"逐位相同"是**分支没被执行的表现,不是数据规律**。

**教训**:两个不同配置给出**完全相等**的输出时,第一反应应该是
"我的配置没生效"。浮点计算里完全相等是极强的信号,几乎总意味着有 bug。

### v2:"窗口塔把图像级精度拉低,应改用 L1 做判定"

**错。** 该结论来自把 `m_all`(含全局标量 `cls_prob`)当作定位分数算像素 AUROC。
`cls_prob` 是**整幅同值**的常数,使 m_all 在缺陷图上整片抬高、良品图上整片压低,
于是像素级 AUROC 衡量的是"哪张图更像缺陷图",不是"哪个像素是缺陷"。

### v3:"5 类均值 95.7 vs 94.6,窗口塔是关键增益"

**部分错。** 两个问题:

1. **混用了不同规模的测试集**:tile/carpet/bottle 用前 25 张子集,
   metal_nut/screw 用全量。而 §3 已证明子集影响可达 20 点 —— 这样的均值没有意义。
2. **`过杀率@P99` 是同义反复**(见 §2.3):阈值本来就是良品分的 P99,
   所以"超过阈值的良品比例"恒等于 1%,与模型好坏无关。

### v4(现行)

全部 5 类改用**全量测试集**,补报 P95,并去掉同义反复的那一列。

## 2. 结论

### 2.1 窗口塔买到的是"位置",没买到"判定"

| 指标 | L1 → full | 变化 |
|---|---|---|
| 定位 pix | 94.2 → 95.6 | +1.4 |
| **判定 pix** | 70.2 → **90.7** | **+20.5** |
| img AUROC | 95.2 → 94.3 | −0.9 |
| **漏检@P95** | 16.6% → **16.3%** | **−0.3 点** |

**12.8× 算力,把像素级定位从 70.2 拉到 90.7,但产线真正买单的漏检率只动了 0.3 个点。**

机制:`img_score = (cls_prob + few_map.max())/2` 是**取最大值**。
L1 的 patch 尺度分支已经能把缺陷处的分数顶起来,`max()` 早就取到了那个峰;
窗口塔把**周围**的像素也修准了,但峰高几乎没变,而 `max()` 只在乎峰高。

→ **若产线只需要"OK/NG",L1 就够,省 92% 算力。**
→ **若要给机械臂/复检定位,则必须上 3×3 窗口塔** —— 这正是级联的价值所在:
   不是"窗口更强",而是"窗口只在需要定位时才付钱"。

### 2.2 均值掩盖了逐类的反向取舍

均值 +20.5 点由这些构成:

| 类 | 判定 pix (L1 → full) | 漏检@P95 (L1 → full) |
|---|---|---|
| tile | 58.6 → 92.2 (+33.6) | 1.2% → 0.0% |
| carpet | 77.1 → 98.7 (+21.6) | 4.5% → 1.1% |
| bottle | 64.6 → 96.5 (+31.9) | 7.9% → 1.6% |
| **metal_nut** | 74.1 → **69.9 (−4.2)** | 1.1% → **7.5%(变差 6.4 点)** |
| screw | 76.8 → 96.2 (+19.4) | 68.1% → 71.4%(无改善) |

**metal_nut 是唯一被窗口塔显著伤害的类**,且漏检率恶化 6.4 点。
这不是噪声:L1(1.1%)、L1+3×3(6.5%)、full(7.5%)单调恶化,方向一致。

合理解释(待验证):metal_nut 的缺陷是**整个螺母的形变/错位**,缺陷区域大、
跨越多个 3×3 窗口。调和平均 `2/(1/a+1/b)` 被**较小值支配** —— 一个窗口内只要
大部分区域是正常背景,该窗口的异常分就低,拉低整个被覆盖 patch 的调和值。
L1 的 patch 尺度反而因为逐点独立而没这个问题。

→ **这是"窗口尺度不适合大范围形变类缺陷"的具体证据**,可用作选档依据:
   产线可先用 L1 的 patch 尺度估计缺陷**面积**,面积大则跳过窗口塔。

### 2.3 `过杀率@P95/P99` 是同义反复,不能再这样报

阈值**就是**良品分数的 P95/P99 分位。因此"超过阈值的良品比例"按定义恒等于
5%/1%,与模型好坏无关。实测完全印证(三档数字一模一样):

| 类 | 良品 N | 过杀@P95(三档) | 过杀@P99(三档) |
|---|---|---|---|
| tile | 33 | 6.1% / 6.1% / 6.1% | 3.0% / 3.0% / 3.0% |
| carpet | 28 | 7.1% / 7.1% / 7.1% | 3.6% / 3.6% / 3.6% |
| bottle | 20 | 5.0% / 5.0% / 5.0% | 5.0% / 5.0% / 5.0% |
| metal_nut | 22 | 9.1% / 9.1% / 9.1% | 4.5% / 4.5% / 4.5% |
| screw | 41 | 4.9% / 4.9% / 4.9% | 2.4% / 2.4% / 2.4% |

**正确报法是 (过杀, 漏检) 这一对**:把过杀固定在 5%,看漏检是多少。
本报告 §1 的漏检列就是这个配对值,过杀列已删除。

另外注意量化效应:良品只有 20~41 张,所以过杀率的最小非零粒度是 1/N
(20 张 → 5.0%,41 张 → 2.4%)。**要报 1% 量级的过杀率,良品样本至少要有几百张。**

### 2.4 真正的瓶颈不是窗口塔,是 screw 的图像级打分

screw 的**定位**极好(判定 pix 96.2,与 research 的 96.0 一致),
但**判定**崩了:img AUROC 75.1,漏检率 68~72% —— 而且**三档都一样**。

→ 加多少窗口都救不了。瓶颈在 `img_score = (cls_prob + few_map.max())/2`
   这个组装方式上,不在窗口预算上。

**这是本次诊断最有价值的发现**:项目当前的算力投入方向(堆窗口)
与瓶颈(图像级打分函数)不匹配。修一个打分函数(0 额外算力)
的收益,大于把算力翻 12.8 倍。

对比:全项目 15 类里 screenshot 之外还有 cable(85.3)、capsule(68.4)、
pill(85.9)等类的 img AUROC 同样偏低 —— 这是**共性缺陷**,不是 screw 个例。

### 2.5 2×2 尺度可以砍(metal_nut 除外)

`L1+3×3`(1916) → `full`(2896,加 2×2):

| 指标 | 变化 | token 成本 |
|---|---|---|
| 定位 pix | 95.3 → 95.6 (+0.3) | **+51%** |
| 判定 pix | 89.6 → 90.7 (+1.1) | |
| img | 94.6 → 94.3 (−0.3) | |
| 漏检@P95 | 16.7% → 16.3% (−0.4) | |

**逐类**:tile −0.4、carpet +0.4、bottle +0.3、screw +0.7 基本持平;
**metal_nut +1.6** —— 恰是那个被 3×3 伤害的类。

→ 2×2 只在"3×3 已经帮倒忙"的类上才有正收益,是**补救**而非增益。
   默认配置建议砍掉 2×2,保留 metal_nut 类的例外开关。

## 3. 与 research 路径的一致性(强验证)

`full` 档在定义上就是 research 路径。**且测试集完全相同** ——
本报告各类的缺陷数 + 良品数,与 `logs/exp_20260908_143906.json` 的
`n_defect` / `n_test` 逐类精确相等:

| 类 | 缺陷 | 良品 | 合计 | research n_test |
|---|---|---|---|---|
| tile | 84 | 33 | 117 | 117 ✓ |
| carpet | 89 | 28 | 117 | 117 ✓ |
| bottle | 63 | 20 | 83 | 83 ✓ |
| metal_nut | 93 | 22 | 115 | 115 ✓ |
| screw | 119 | 41 | 160 | 160 ✓ |

逐类 4-shot 对照:

| 类 | 本报告 full img | research img | 差 | 本报告 full 判定pix | research pix | 差 |
|---|---|---|---|---|---|---|
| tile | 99.9 | 99.9 | **0.0** | 92.2 | 91.8 | +0.4 |
| carpet | 99.6 | 99.8 | −0.2 | 98.7 | 98.9 | −0.2 |
| bottle | 99.1 | 99.1 | **0.0** | 96.5 | 95.7 | +0.8 |
| metal_nut | 98.0 | 97.5 | +0.5 | 69.9 | 61.5 | +8.4 |
| screw | 75.1 | 71.6 | +3.5 | 96.2 | 96.0 | +0.2 |

**4/5 类的 img AUROC 吻合在 ±0.5 点内(tile/bottle 完全相等)。**
重建口径(verify_rebuild.py,max|Δ|=0 逐位对拍通过)与 research 路径一致。

**残余差异的原因**:gallery 采样细节与 research 不完全相同(本报告用
`cache_good.py` 重建的 gallery),metal_nut 的 +8.4 点最可能源于此 ——
该类 4-shot 只有 4 个参考样本,对采样极敏感。

**至此 §4-3 的待办关闭**:定位口径不是"我发明的分数",它是 pipeline 的
`few_map`,可从两次公开调用精确还原(`m_all_few − m_all_zero`,实测差 7e-9)。

## 4. 待办(不得当结论引用)

1. **zero-shot 口径未测**:本报告全部为 4-shot。zero-shot 下 few 分支退化,
   `img_score = cls_prob` 行为可能完全不同。
2. **metal_nut 反向的机制未证实**:§2.2 的"大范围形变 vs 调和平均"是**推测**,
   未做实验验证(可通过统计缺陷 GT 面积与档位增益的相关性来检验)。
3. **其余 10 类未测**:本报告只有 5 类。cable/capsule/pill 等 img AUROC 偏低的类
   是否也呈现"窗口塔救不了图像级"的模式,需在 15 类全量上复核。
