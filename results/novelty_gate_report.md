# novelty-gated 良品入库 —— 复现与负结果(2026-09-11)

> 复现对象:**arXiv 2608.17775 §III-B2 Eq.(4)** 的自校准新颖性门控
> (Training-Free Human-in-the-Loop Anomaly Detection via Memory Bank Correction)
> 数据:**MVTec 7 类**,本地缓存特征,纯 numpy,**零次推理、未使用远程 GPU**
> 脚本:`scripts/exp/novelty_gate.py`(单尺度)、`scripts/exp/novelty_gate_ms.py`(多尺度)
> 原始输出:`logs/novelty_gate_k{1,4,8}.txt`、`logs/novelty_gate_ms_k{1,4}.txt`

---

## 0. 一句话结论

**复核驱动扩库本身有效(冷启动最大 +15pt),但那个"新颖性门控"在我们的管线上没有用处 ——
它与"不插"不同、与"全插"相同。单尺度和多尺度两个口径都得出同一结论。**

---

## 1. 实验设置

| | |
|---|---|
| 初始 gallery | `k` 张良品(**k = 1 / 4 / 8**) |
| 评审池 | calib 中除去 gallery 的其余良品图(产线语义:"被报警→复核→确认是良品") |
| held-out | 良品池的另一半,**只用于测 AUROC**,从不参与 gallery/τ/校准的任何一步 |
| τ_nov | 评审池 token 到**基线库**的 1-NN 距离中位数,**开跑前定一次**(论文原做法) |
| 距离口径 | `0.5·(1−max cos)`。特征已 L2 归一化 ⇒ `= ‖a−b‖₂²/4`,是欧氏距离的严格单调变换,故分位数与论文等价 |
| 报告口径 | **held-out image AUROC** |

**两种打分口径**(结论在两者上一致):

- **单尺度** `novelty_gate.py`:只用 `full` patch token(225),`loc.max()`。
- **多尺度** `novelty_gate_ms.py`:**与生产管线同口径** ——
  `full` + 2×2(196 窗)+ 3×3(169 窗),窗口用 `_scatter_harmonic` 调和合并到 225 格,再取 max。
  已与 `shot_scaling.py::few_map_of` 逐张对拍,**最大绝对误差 3.7e-8**。

**臂**:`none`(基线)/ `ungated`(全插)/ `gated`(τ=中位数)/ `gated_q25` / `gated_q75` /
**`rnd_matched`(随机插与 gated 同数)** / `full`(全部评审池入库,上界参照)。

> ★ **`rnd_matched` 是本实验补的对照臂,论文没有。** 只对比 gated vs ungated 分不清
> "门控有分辨力"和"门控只是插得少";同数随机把这两件事拆开。

## 2. 主结果(跨类均值,7 类)

| 口径 | k | `none` | `ungated` | `gated` | `gated_q25` | `gated_q75` | **`rnd_matched`** | `full` | **gated − rnd** | **gated − ungated** |
|---|---|---|---|---|---|---|---|---|---|---|
| 单尺度 | **1** | 82.7 | 94.4 | **94.6** | 94.3 | 94.4 | **92.6** | 94.4 | **+2.1** | +0.2 |
| 单尺度 | **4** | 90.9 | 94.2 | 94.2 | 94.2 | 94.4 | 94.1 | 94.2 | +0.1 | 0.0 |
| 单尺度 | **8** | 93.1 | 94.4 | 94.3 | 94.4 | 94.4 | 94.2 | 94.4 | +0.2 | −0.1 |
| **多尺度** | **1** | 81.1 | 96.2 | **96.5** | 96.3 | 96.1 | **95.0** | 96.2 | **+1.5** | +0.3 |
| **多尺度** | **4** | 92.1 | 96.0 | 96.1 | 96.0 | 96.0 | 95.7 | 96.0 | +0.4 | +0.1 |

gated 的插入率(随库增长而下降,所以低于名义分位数):单尺度 k=1 时 21–42%、k=4 时 32–48%、
k=8 时 45–49%;多尺度 k=4 时 43.6%、k=1 时更低。

**三条读出(两个口径都成立):**

1. **复核扩库 = 主效应,且随初始库变大而递减**:冷启动 +11.7(单)/ +15.1(多)pt,
   到 k=4 只剩 +3.3 / +3.9pt。**且 `ungated` 在全部 5 个设置 × 7 类 = 35 格里,
   没有一格显著低于 `none`** —— **唯一的反例格是 capsule 多尺度 k=4**:
   `none` 92.1±0.5 > `ungated` 91.7±0.0 > `gated` 91.9±0.1 …… 且 `rnd_matched` **92.2±0.7**。
   即在该格上**插入臂全体不比"不插"好,而门控还输给同数随机**。
   但 `capsule` 良品池只有 **23 张** ⇒ 评审池仅 **7 张**(见各行表头),
   这一格的实际信息量极小,不足以支撑"插入有害"的结论,只是**不能忽略**。
   (同一类在单尺度 k=4 上 `none` 90.7±3.0 → `ungated` 93.1±0.0 是**受益**的,
   两个口径方向相反 ⇒ 更应读作噪声。)

**⚠️ 一处反常,如实记录不平滑**:多尺度 k=1 的 `capsule` `none` = **41.5±1.0**,
**显著低于随机(50)**。其它 6 类的 `none` 都在 67.8–99.1。
即:在 capsule 冷启动 1-shot 时,基线打分的**排序方向是反的**。
本报告不给因果归因(未做消融),**但引用 capsule 任何数字时都必须一并引用这 41.5**。
2. **门控的选择准则确实带信息,但只在冷启动**:k=1 时 gated − rnd = **+2.1**(单尺度,5 胜 2 平 0 负)
   / **+1.5**(多尺度,6 胜 1 负);多尺度 k=1 的 cable 差 **+4.9**、screw **+2.9**。
   到 k=4 就塌成 +0.1(单)/ +0.4(多)。**库一大,"插哪些"就不重要了。**
3. ★ **但门控相对"全插"始终没有优势**:`gated − ungated` 在 5 个设置里全在 **±0.3pt** 内。
   既然全插既不伤我们、也不额外花钱,**门控就没有存在的理由**。

**交叉验证**:多尺度 `full`(≈20 张全入库)的 screw = **92.4**,
与 `shot_scaling.py` 独立算出的 k=16 screw fewmax = **92.3** 对得上 —— 两套实现互相印证。

## 3. 为什么门控在我们这里没用(机制)

论文的伤害机制(§IV-D2 原文):*"their banks are comparatively large, their remaining errors
genuinely ambiguous, so FP corrections add patches the bank already covers, and **the redundant
insertion perturbs previously correct decisions**"* —— 这是 **PatchCore 特有**的:

| | 论文(PatchCore) | 本项目(WinCLIP 复现线) |
|---|---|---|
| 库 | 贪心 k-center **核心集**(~1%,toothbrush 仅 470 patch) | gallery patch 的**原样拼接**(k=1 即 225) |
| 打分 | 最近邻距离,**再按到最近正常样本的距离重加权** | `0.5·(1 − max cos)`,取该图 patch 的 **max** |
| 加 patch 的后果 | 扰动了核心集的距离统计 → **可能变差** | max-sim 只增不减 → 每张图分数**只降不升**,**不可能变差** |

**⇒ 我们的打分对库大小是单调的,论文要防的那种"伤害"在我们这里不存在,
门控自然也就无从发挥作用。**

> ⚠️ 我原本预判**多尺度可能翻盘** —— 因为调和合并带**覆盖计数** `cf`,
> 窗口覆盖范围会随入库 token 改变,理论上可能破坏单调性。**实测没有翻盘**:
> 多尺度下 gated − ungated 仍是 +0.3 / +0.1。单调性论证在实测层面站得住。

## 4. 与论文的分歧(必须写明,别混为一谈)

| | 论文 | 本次实测 |
|---|---|---|
| 门控在哪种库上有用 | **成熟库**(防伤害) | **冷启动的小库**(选择题),成熟库上无效 |
| 无门控的伤害 | 成熟库上 6 类变平/变负,gate 救回 5 类 | **观察不到**;35 格无一显著变差 |
| 增益来源 | 教"正常性",不是记缺陷 | 一致:插入的全部是良品 patch |
| grid | 唯一 gate 也救不了的类 | 未涉及(7 类里没有 grid) |

**不构成矛盾**:两者测的是不同的库结构与不同的打分函数。正确表述是
**"该门控是 PatchCore 核心集 + 距离重加权打分的专用补丁,不具迁移性"**,
而不是"论文错了"。

## 5. 口径限制(引用这些数字时必须一并给出)

1. **7 类**(MVTec),非 15 类;是本地缓存可用的类,不是完整协议。
2. **"人工复核"是模拟的**:评审池天然全是良品(MVTec 只在 test/good 有良品),
   故等价于论文的 FP-only 分支。**论文自陈 "Feedback is simulated from ground truth"
   是同一处局限**,我们同样受此限。
3. **n=3 reps**;多数类逐格标准差 ±0.2–3pt,**低于 1pt 的逐类差异是噪声**,
   只读跨类均值与胜负计数。
4. `tile`/`hazelnut`/`metal_nut` 在多数设置上已接近饱和,无区分度。
5. `rnd_matched` 每轮消耗随机数 ⇒ **同一 run 内各臂共享同一批 gallery**(配对成立),
   但改动臂列表则不可复现。
6. **门控省的是 patch 数/库体积,不是复核张数** —— 所有臂都复核完整个评审池。
   论文"省到 43% 复核成本"来自**提前停止**,不来自门控。
7. `k=8` 只跑了单尺度;**`k=1/4` 两个口径都有**。

## 6. 这条线索的处置建议

- **不要**把 novelty gate 加进管线。没有收益,只增加一个需要标定的阈值。
- **要**保留的正面结果:**复核扩库有效且无害**,冷启动收益最大(+12~15pt),
  且**插入到评审池 ~50–80% 就饱和**(见各 log 的逐轮曲线)⇒ 这是"该复核多少张"的
  直接依据,**且阈值仍只来自良品,不碰 GT**。
- 若要继续,真正的空白在**像素级修正** —— 论文 §VI-A 自陈
  *"Correction is **image-level only; pixel-level correction remains future work**"*,
  而本项目整条线是像素级的。但那条路尚无现成实现可复现,不能照抄。

## 7. 已知的过程错误(留痕)

**错误一:`score_from_best` 方向取反(单尺度版)**
初版写成 `best.max(axis=1)` —— 那取的是"最正常的 patch",等于把 `0.5(1−max cos)` 反过来。
后果:所有图(好坏不分)分数挤在 0.0009、**AUROC 恒等于 ~50**、且**插入任何 patch 都不改变它**,
于是 `gated` 与 `none` 一字不差。**不报错、不 NaN,只是结论全为零**。
修正为 `best.min(axis=1)` 后与 `shot_scaling` 原路径逐张对拍,最大绝对误差 1.8e-7。

**错误二:多尺度版 `banks` 从未增长**
`upd()` 更新了打分侧的 `bs`,却漏了候选侧距离要用的 `banks`,
于是门控永远拿**基线库**算候选距离,而论文 Eq.(4) 的判据是 `min_{m∈M^(r)}`(**当前**库)。
破绽是插入率**恒定等于名义分位数**(50.0%/75.0%/25.0%,整齐得不正常);
而 AUROC 照常变化,从结果上完全看不出来。修正后插入率随库增长降到 43.6%/68.2%/17.5%。

> **两次都是"沉默的错误"**:不抛异常、不产生 NaN,只是让结论静悄悄地变成空集。
> 教训:插入率、计数器这类**副产物**是发现这类错误的唯一线索,必须打印出来看。
